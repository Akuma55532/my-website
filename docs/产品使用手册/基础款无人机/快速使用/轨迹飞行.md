# 轨迹飞行

本节以 **1 架 FanciSwarm® 基础款无人机在 UWB 室内定位环境中飞圆形轨迹** 为例，说明从确认默认轨迹、编译工程到起飞、运行轨迹、降落和关机的完整操作流程。

本节属于快速使用。首次操作请使用工程提供的默认轨迹，不要修改源代码；确认整套系统可以稳定运行后，再进行自定义轨迹开发。

## 操作前准备

开始前请确认：

- 已完成 [环境部署](./环境部署.md)，4 个 UWB 基站的位置和定位参数均已设置；
- 已完成 [ROS 工程部署](./ROS工程部署.md)，`fcu_core` 工程已导入；
- 电脑已安装 Ubuntu 20.04、ROS Noetic、`ros-noetic-serial` 和 Eigen；
- 无人机标签 ID 已设置为 `1`，对应通信节点 `001`；
- 飞行场地空旷，现场人员已了解本节中的安全操作要求。

:::danger[必须按顺序操作]

轨迹飞行涉及旋转的螺旋桨。必须先完成定位、ROS 通信、RViz 轨迹和遥控飞行检查，再解锁并运行轨迹。任一检查未通过时，禁止起飞。

:::

## 一、确认默认轨迹

所有位置点和轨迹指令均在 ROS 工程的 `fcu_core/src/fcu_mission.cpp` 文件中定义。单机轨迹飞行使用通信节点 001，对应函数：

```cpp
void execute_mission_001(void)
```

工程默认轨迹为圆形轨迹，采用极坐标方程表示。下图中的默认圆轨迹圆心为 `(2, 2)`，半径为 `1`，因此默认起点坐标为 `(3, 2)`。

![fcu_mission.cpp 中通信节点 001 的默认圆形轨迹](/产品使用手册/使用手册/基础款/mission_001.png)

:::warning[坐标单位不要混淆]

ROS 轨迹中的位置单位为米，因此起点 `(3, 2)` 表示基站坐标系下 `X = 3 m`、`Y = 2 m`。环境部署时，App 中填写的基站坐标单位为厘米，两者不能混用。

:::

首次验证时请保留默认轨迹。需要设计自定义轨迹或目标点时，应在后续二次开发部分学习 `fcu_mission.cpp` 的代码结构和修改方法。

## 二、编译 ROS 工程

### 1. 克隆依赖工程

`fcu_core` 依赖 `quadrotor_msgs`。在工作空间的 `src` 文件夹中打开终端，选择一个可访问的仓库地址执行克隆。

使用 Gitee：

```bash
cd ~/ros-ws/src
git clone https://gitee.com/fancinnov/quadrotor_msgs.git
```

使用 GitHub：

```bash
cd ~/ros-ws/src
git clone https://github.com/fancinnov/quadrotor_msgs.git
```

工程地址：[GitHub](https://github.com/fancinnov/quadrotor_msgs) / [Gitee](https://gitee.com/fancinnov/quadrotor_msgs)

如果 `~/ros-ws/src/quadrotor_msgs` 已经存在，请勿重复克隆。

### 2. 运行 catkin_make

`catkin_make` 必须在工作空间根目录 `ros-ws` 下运行，不能在 `src` 文件夹下运行：

```bash
cd ~/ros-ws
catkin_make
```

### 3. 确认编译成功

等待进度达到 `100%`，并确认终端没有出现编译错误。

![catkin_make 编译达到 100%](/产品使用手册/使用手册/基础款/ros-build.png)

编译成功后，`ros-ws` 下会生成 `build` 和 `devel` 文件夹：

- `build`：存放编译过程中的中间文件和构建产物；
- `devel`：存放开发环境中的可执行文件、库和环境配置脚本。

![编译后生成 build 和 devel 文件夹](/产品使用手册/使用手册/基础款/ros-build2.png)

如果编译失败，请从终端出现的第一条错误开始排查，确认 `fcu_core` 和 `quadrotor_msgs` 均位于 `~/ros-ws/src` 后再重新编译。

## 三、确认基站与定位参数

1. 按照 [环境部署](./环境部署.md) 中的说明摆放并固定 4 个基站；
2. 在 FanciSwarm App 中确认坐标偏航角、标签总数和 4 个基站坐标正确；
3. 将本次飞行无人机的标签 ID 设置为 `1`；
4. 参数写入完成后重启无人机。

标签 ID `1` 对应 ROS 通信节点 `001`，即 `fcu_bridge_001.cpp`。参数设置页面的使用方法也可参阅通用教程中的 [App 使用手册](../../../通用教程/App使用手册.md)。

## 四、安装 UWB 模组并放置无人机

### 1. 安装 UWB 模组

新款 FanciSwarm® 无人机采用 UWB 模组与机体分离的设计。飞行前，请将 UWB 模组正确连接至无人机，并使模组竖直朝上。

![新款 FanciSwarm 无人机 UWB 模组的安装位置](/产品使用手册/使用手册/基础款/FanciSwarm_installation-new.png)

旧款无人机已经板载 UWB 模组，无需执行这一步。

### 2. 确认轨迹起点

默认圆形轨迹的起点为基站坐标系下 `(3, 2)`，即 `X = 3 m`、`Y = 2 m`。

### 3. 放置无人机

将无人机放置在默认轨迹起点处，并满足以下要求：

- 无人机放在水平地面上；
- 机尾朝向操作者；
- 机头方向与基站坐标系方向一致；
- 无人机与人员、墙壁、杂物和任意基站之间保留足够安全距离；
- 起点及完整圆形轨迹均位于可安全飞行区域内。

:::danger[不要只检查起点]

默认轨迹半径为 1 m。除了起点 `(3, 2)`，还必须确认整条圆形轨迹及其外围安全空间内没有人员、墙壁、基站和其他障碍物。

:::

## 五、重启无人机并开启基站

1. 按复位键重启 FanciSwarm® 无人机；
2. 开启 4 个基站，开启顺序不限；
3. 观察无人机和基站的 LED6，即 UWB 指示灯；
4. LED6 快速闪烁时，表示无人机 UWB 定位正常，可以继续操作。

如果 LED6 没有快速闪烁，请勿起飞。重新检查 UWB 模组连接、基站摆放和定位参数，然后重启无人机与基站再次尝试。

## 六、运行 ROS 工程

### 1. 确认控制连接关系

:::danger[App 与 ROS 不能同时连接]

FanciSwarm App 与 ROS 不能同时连接同一架无人机。同一时刻只能保留其中一种连接方式。准备使用 ROS 时，请先断开 App 与无人机的连接。

:::

遥控器可以与 ROS 同时连接无人机。两者同时连接时：

- 使用 ROS 控制：将遥控器 CH7 三段开关切换至自主模式档位；
- 使用遥控器直接控制：将 CH7 切换至中间的位置模式档位；
- 遥控器油门始终有效：油门低于 `0.4` 时无人机下降，高于 `0.6` 时无人机上升，处于 `0.4～0.6` 时保持悬停；
- 希望由 ROS 控制飞行高度时，遥控器油门应持续保持在 `0.4～0.6` 范围内。

![遥控器 CH5 和 CH7 三段开关位置](/产品使用手册/使用手册/基础款/rc_ch7_ch5.png)

### 2. 加载工作空间环境

打开一个新终端，执行：

```bash
cd ~/ros-ws
source devel/setup.bash
```

### 3. 配置 USB 通信权限（仅 USB 通信）

基础款默认使用网口通信，不使用 USB 通信时跳过本步。

如果使用 USB 虚拟串口通信，官网旧教程使用下面的命令临时开放设备权限：

```bash
sudo chmod 777 /dev/ttyACM0
```

该权限会在设备重新连接后失效，仅用于当前测试。长期使用时，建议将当前用户加入 `dialout` 用户组，并在重新登录系统后生效：

```bash
sudo usermod -aG dialout "$USER"
```

### 4. 确认网络

- 单机轨迹飞行：电脑连接该无人机的 Mlink Wi-Fi；
- 多机飞行：电脑和所有无人机接入同一个局域网。

本节为单机轨迹飞行，请确认电脑连接的是标签 ID 为 `1` 的无人机，并再次确认无人机已重启、4 个基站已开启且 LED6 快速闪烁。

### 5. 启动工程

在已执行 `source devel/setup.bash` 的终端中运行：

```bash
roslaunch fcu_core fcu_core.launch
```

![加载工作空间环境并启动 fcu_core](/产品使用手册/使用手册/基础款/ros-run.png)

### 6. 确认连接成功

终端出现以下提示，并持续打印无人机心跳、电压和电流信息，表示通信节点 001 连接成功：

```text
fcu_bridge 001 connect succeed!
```

![fcu_bridge 001 连接成功并输出无人机状态](/产品使用手册/使用手册/基础款/ros-run2.png)

如果终端显示 `fcu_bridge 001 connect error!`，请停止操作并检查：

- 电脑是否连接了正确的 Mlink Wi-Fi；
- `fcu_bridge_001.cpp` 中的 `DRONE_IP` 是否正确；
- 无人机是否已开机并完成重启；
- App 是否仍与无人机保持连接；
- 修改参数后是否重新执行了 `catkin_make`。

## 七、检查 RViz 定位轨迹

ROS 工程启动后会自动打开 RViz。RViz 是 ROS 的三维可视化工具，用于显示无人机位置和飞行轨迹。

![RViz 中的坐标轴和无人机位置点](/产品使用手册/使用手册/基础款/rviz.png)

右侧三维视图中：

- 红色坐标轴代表 X 轴；
- 绿色坐标轴代表 Y 轴；
- 蓝色坐标轴代表 Z 轴；
- 红色点代表无人机在世界坐标系中的当前位置。

在无人机仍处于锁定状态、螺旋桨完全静止时，将无人机垂直拿起并沿场地缓慢走一圈，同时观察 RViz 中的位置点和轨迹是否随实际移动连续、方向一致且没有明显跳变。

:::danger[检查轨迹时禁止解锁]

手持无人机检查 RViz 轨迹前，必须确认无人机处于锁定状态。严禁拿起已解锁或螺旋桨正在转动的无人机。

:::

只有定位轨迹显示正常，才能继续下一步。

## 八、飞行前检查

起飞前请逐项确认：

1. 无人机放置在水平面，操作者位于机尾方向；
2. 无人机前、后、左、右至少 2 m 范围内无人员、墙壁和杂物；
3. 完整轨迹范围内没有基站、线缆、支架或其他障碍物；
4. 室内地面具有清晰、非单一且易识别的纹理，无过暗、过亮和强反光区域；
5. 电池连接线已固定，不会被螺旋桨刮到；
6. 每个螺旋桨均安装牢固，没有破损、老化或变形；
7. 无人机和遥控器电量充足；
8. FanciSwarm® 固件版本与 FanciSwarm App 版本符合官网当前要求；
9. LED6 快速闪烁，ROS 终端持续收到节点 001 的正常状态数据；
10. RViz 中的位置和轨迹已经检查无误。

### 室内地面纹理要求

推荐使用不同颜色交替铺设的软质地垫。建议单块尺寸为 `30 × 30 × 1 cm`，并混合白色、蓝色、灰色等多种颜色，以提高光流模块的纹理识别效果，同时减轻意外落地时的冲击。

[基础款地垫购买链接（淘宝）](https://e.tb.cn/h.hMiitwrtPywzujw?tk=RVcs456ddxg+CZ225)

![多种颜色交替铺设的室内飞行地垫示例](/产品使用手册/使用手册/基础款/block.png)

:::warning[以下地面禁止直接起飞]

纯色大理石瓷砖、颜色单一的木地板、强反光地面，以及缺少有效纹理或只有高度重复图案的地面，都可能影响光流定位。无法确认场地是否合适时，请先联系幻思创新工程师确认。

:::

选配高精度 GNSS 模组并在室外飞行时，无需依靠地面纹理进行光流定位，但必须先确认 GNSS 定位状态满足起飞要求。

## 九、基站开启状态下进行遥控飞行测试

在正式运行 ROS 轨迹前，先使用遥控器进行一次短距离、低高度飞行测试：

1. 将 CH7 三段开关切换至中间位置，即位置模式；
2. 在空旷区域完成起飞、悬停、小范围移动和降落；
3. 确认无人机没有异常漂移、抖动或突然改变高度；
4. 确认飞行稳定并重新锁定无人机后，再继续运行 ROS 轨迹。

若遇到飞行异常，可将 CH7 切换至最上方、靠近 CH8 的档位，即姿态模式，改由操作者接管并安全降落。

## 十、清除 RViz 现有轨迹

运行新的轨迹前，应先清除 RViz 中已有的轨迹显示：

1. 回到正在运行 `roslaunch` 的终端；
2. Windows/Linux 键盘按 `Ctrl + C` 停止当前 ROS 工程；Mac 虚拟机如果已将中断操作映射为 `Command + C`，则按 `Command + C`；
3. 等待节点依次退出，再按回车键；
4. 重新执行“运行 ROS 工程”中的加载环境和启动命令；
5. 确认节点 001 再次连接成功，RViz 中旧轨迹已经清除。

![使用 Ctrl+C 退出 ROS 工程并清除 RViz 轨迹](/产品使用手册/使用手册/基础款/ros_exit.png)

## 十一、开始运行轨迹

ROS 工程提供键盘指令集。工程运行后，在终端输入一个指令字符并按回车键，即可下发相应指令。

| 指令 | 功能 | 执行后的状态 |
| --- | --- | --- |
| `a` | 解锁 | 电机进入可运行状态 |
| `t` | 一键起飞 | 上升到设定高度并悬停 |
| `r` | 运行轨迹 | 开始运行默认圆形轨迹 |
| `s` | 停止轨迹 | 停止圆形轨迹并悬停 |
| `l` | 一键降落 | 下降并着陆 |
| `d` | 锁定 | 电机锁定 |

所有指令字符均在 `fcu_command.cpp` 中定义。快速使用阶段请使用上表中的默认指令，不要修改指令映射。

### 1. 解锁前确认

- 起落架结构稳固，无松动或损坏；
- 无人机位于轨迹起点 `(3, 2)`；
- 无人机机尾朝向操作者；
- 飞行区域内没有人员和障碍物；
- ROS、UWB、RViz 和遥控飞行测试均已通过。

对于未搭载高精度 GNSS 模组的机型：无人机启动提示音结束后，在保持锁定的状态下，将无人机垂直拿起一次，抬到距离地面超过 1 m 后再放回起点。激光测距正常时才能解锁；否则无人机会发出连续报警音并保持强制锁定。

对于搭载高精度 GNSS 模组的机型：首次开机后等待 GNSS 模组蓝色 LED 长亮，确认信号良好后再解锁。蓝色 LED 未保持长亮时，系统可能报警并拒绝解锁。

### 2. 输入 `a` 解锁

在 ROS 终端中输入：

```text
a
```

按回车键后，终端打印“解锁”。

![在 ROS 终端输入 a 解锁无人机](/产品使用手册/使用手册/基础款/a_armed.png)

此时 Mcontroller 右侧 LED 绿灯点亮并伴随启动声音，表示无人机已经解锁。

### 3. 输入 `t` 起飞

```text
t
```

按回车键后，终端打印“起飞”。

![在 ROS 终端输入 t 一键起飞](/产品使用手册/使用手册/基础款/t_takeoff.png)

无人机将上升到 FanciSwarm App 中设置的起飞高度并保持悬停。确认悬停稳定后再运行轨迹。

### 4. 输入 `r` 运行轨迹

```text
r
```

按回车键后，终端打印“运行”。

![在 ROS 终端输入 r 开始运行轨迹](/产品使用手册/使用手册/基础款/r_run.png)

无人机开始运行默认圆形轨迹。操作过程中持续观察无人机、ROS 终端和 RViz，不得离开控制位置。

## 十二、停止轨迹并降落

### 1. 输入 `s` 停止轨迹

```text
s
```

按回车键后，终端打印“停止”。

![在 ROS 终端输入 s 停止运行轨迹](/产品使用手册/使用手册/基础款/s_stop.png)

无人机停止圆形轨迹并保持悬停。

### 2. 输入 `l` 降落

```text
l
```

按回车键后，终端打印“降落”。

![在 ROS 终端输入 l 一键降落](/产品使用手册/使用手册/基础款/l-land.png)

等待无人机完全着陆、电机停止转动。

### 3. 输入 `d` 锁定

确认无人机已经着陆后输入：

```text
d
```

按回车键后，终端打印“锁定”。

![在 ROS 终端输入 d 锁定无人机](/产品使用手册/使用手册/基础款/d_disarmed.png)

无人机锁定后，电调指示灯熄灭；Mcontroller 右侧 LED 绿灯熄灭、红灯点亮。

:::danger[必须先降落再锁定]

禁止在无人机仍处于空中时输入 `d`。正常结束顺序必须为：`s` 停止轨迹 → `l` 降落 → 确认完全着陆 → `d` 锁定。

:::

## 十三、退出 ROS 并关闭设备

### 1. 退出 ROS 工程

确认无人机已锁定后，回到 ROS 终端：

1. Windows/Linux 键盘按 `Ctrl + C`；Mac 虚拟机如果已将中断操作映射为 `Command + C`，则按 `Command + C`；
2. 等待所有 ROS 节点退出；
3. 按回车键返回终端命令行。

![轨迹飞行结束后退出 ROS 工程](/产品使用手册/使用手册/基础款/ros_exit%20(1).png)

### 2. 关闭无人机和基站

如果不再继续飞行：

1. 关闭无人机电源；
2. 断开无人机电池连接；
3. 关闭 4 个 UWB 基站；
4. 妥善收纳无人机、电池、基站和遥控器。

及时断开电池可以避免持续耗电和电池过度放电。至此，单机轨迹飞行流程完成。
